# HAK Lương Offline V10.4 — v2.1.5

Trạng thái: thử nghiệm có kiểm soát

Theo yêu cầu của chủ (23/11/2026): "cho chọn thư mục để cài đặt sao lưu". Trước đây thư mục SQLite cố định trong thư mục dữ liệu (quyết định (a) ở #113); nay chọn được thêm nơi lưu. Không sửa `main/storage.js`, `main/storage-paths.js` (CI khóa), `engine.js`, `hr.js`, workflow CI; không đổi công thức, lược đồ dữ liệu.

## Thay đổi
1. **Khóa cài đặt MỚI `sqliteDir`** (chỉ thêm; cấu hình cũ đọc bình thường), làm giống thư mục JSON (`jsonDir`): `main.js` thêm IPC `sqlite-get` / `sqlite-set-dir` / `sqlite-clear-dir`, `preload.js` thêm `hakSqlite`.
2. **Cách ghi an toàn:** bản chụp SQLite vẫn ghi trong thư mục dữ liệu (`backups`) TRƯỚC như cũ; sau đó `main/sqlite-storage.js` chép có kiểm SHA-256 (tệp tạm + fsync + rename) bản mới nhất (`data-snapshot.sqlite`) và bản lịch sử sang thư mục đã chọn, rồi dọn theo cùng quy tắc giữ bản. Thư mục mất kết nối (USB chưa cắm / ổ mạng mất) → báo lỗi ở danh sách bản sao lưu, sao lưu JSON không bị chặn, bản trong thư mục dữ liệu luôn còn, app không tự tạo thư mục mất kết nối.
3. **Màn hình** (tab "Lịch & thư mục sao lưu"): dòng "Sao lưu SQLite" có "Chọn / Chuyển…" (chép các bản chụp hiện có sang thư mục mới, kiểm SHA-256, không xóa bản cũ), "Về mặc định" (bỏ cấu hình, bản đã chép giữ nguyên), Mở, Kiểm tra, Dung lượng. Thư mục SQLite không được lồng với thư mục dữ liệu / JSON / Full Backup / dự phòng / chứng từ / OCR.

- Chưa nghiệm thu trên Windows thật (đường dẫn ổ khác / USB / NAS / Google Drive đồng bộ).
- Khôi phục từ bản chụp SQLite (khi data.sqlite hỏng) vẫn đọc bản trong thư mục dữ liệu; bản ở thư mục đã chọn dùng để cất ngoài máy / chép tay về — chưa tự đọc từ đó.
